One PR per section, one dev each, in dependency order; each PR must be safe
at its own landing (L-G): 1 first (the registry exists before any store
import); 2 needs 1; 3 is independent of 1–2; 4 needs 1–2; 5 needs 3 (no
trim before merge semantics and the install-mode stamp); 6 — the owning
setup-write-path PR — needs 2, 3, 5; 7 needs 2–6; 8 needs 2, 4, 7; 9 needs
8; 10 needs 8; 11 (integration) needs all. Archive order at the end:
`rename-agentboard-to-kawai`, then `openrouter-provider`, then this change
(design D11) — re-check the REMOVED and MODIFIED blocks' texts at rebase.
Every task cites oracle ids from design.md (L#, D9 rows, P#, D#, D12) and
the delta-spec scenarios it implements; a test that covers a spec scenario
names it with `// @covers`. Security invariants (P1, P7) apply to every
task: no credential value in SQLite, backups after the migration commit,
logs, wire logs, client payloads, or agent env beyond the composed
token/header path; example hosts only in tests and fixtures.
