# Proposal

## Why

The product is Kawai, and the packages are already `@motuslabs/kawai` and `@motuslabs/agent-runtime`, but the runtime still uses the name it was forked from. At `f52963d0` operators set 37 distinct `AGENTBOARD_*` variables read in 23 server and client source files (41 names across installers, CI, and tests). Data lives in `~/.agentboard/agentboard.db`, beside `agentboard.log`, `chat-wire/`, `chat-workers/`, `chat-tasks/`, and `backups/agentboard-*.db`. The release ships `bin/agentboard`, the installers create `agentboard.service` and `com.agentboard`, and the tmux session is `agentboard`. Everything built since then uses the Kawai name: `KAWAI_CLAUDE_PATH`, `KAWAI_CODEX_PATH`, `KAWAI_UPDATE_ENDPOINT`, `KAWAI_BUILD_VERSION`, `KAWAI_METRICS_*`, `KAWAI_TEST_*`, and the user-level `~/.kawai/` files (`groups/`, `routing/`, `teams.json`, `outbound.json`, `profiles.json`, `providers.json`, `credentials.json`). One install therefore has two prefixes and two home directories. Renaming the rest at once, with a migration path, ends the split before more operators, scripts, and agent teams depend on the old names.

## What Changes

The change stays one executable change with six ordered internal task groups, carried by one serialized writer because they share `config.ts`, `db.ts`, `SessionManager.ts`, the e2e harness, and `AGENTS.md`:

1. **Env aliases — BREAKING (deprecated, still accepted):** every `AGENTBOARD_<NAME>` environment variable becomes `KAWAI_<NAME>`, for example `KAWAI_CHAT_ENV`, `KAWAI_DB_PATH`, `KAWAI_REMOTE_HOSTS`, and `KAWAI_CHAT_FIXTURE`. The old name is still read when the new one is unset or empty, with one deprecation warning per variable that never shows the value. If both are set, `KAWAI_*` wins. CI, the test preload, Playwright config, and the fixture spec lister (`scripts/e2e-fixture-specs.ts`) move to the new names.
2. **Client storage keys:** browser storage keys become `kawai-settings`, `kawai-theme`, `kawai-workspace`, and `kawai-session`. Each old key is copied over once when the new key is missing, then removed.
3. **Data-home migration — BREAKING (migrated, backup first):** the default data directory becomes `~/.kawai/`, beside the existing user-level files. Files: `kawai.db`, `kawai.log`, `chat-wire/`, `chat-workers/`, `chat-tasks/`, `backups/`, `tmux-server.pid`, and the dev TLS pem files. On first start with default paths, the server takes a verified backup of the legacy database, writes an intent record, moves the legacy data with the database last, and renames the db, log, and backup files to the `kawai` stem. If anything cannot move, or another process still holds the legacy database, nothing is left half-moved and the server runs on `~/.agentboard/`; a process that dies mid-move is rolled forward or back at the next start. `~/.agentboard/app` and `~/.agentboard/bin` are not touched.
4. **tmux session — BREAKING (migrated):** the default tmux session becomes `kawai`, and per-connection sessions become `kawai-ws-*`. On startup, an existing `agentboard` session is renamed when no `kawai` session exists, and stored window targets are rewritten in the same step (and idempotently at any later start that finds them). Startup pruning also removes leftover `agentboard-ws-*` sessions. Remote-host discovery treats both `kawai` and `agentboard` as managed. No session with windows is ever killed.
5. **Release, updater, installers and services — BREAKING (transition):** the release binary becomes `bin/kawai`, and the release tarballs become `kawai-<platform>.tar.gz`. For a transition window, releases also publish `agentboard-<platform>.tar.gz` with the same build as `bin/agentboard`, and the checksum file lists all eight. The updater accepts install roots whose binary is named `kawai` or `agentboard`; in a legacy root it installs the new build under both names. Source runs install to `~/.kawai/app`. Service names become `kawai.service`, `com.kawai`, and `com.kawai.logrotate`; re-running an installer retires the legacy unit or agent; restarts target whatever unit or label launched the process. `KAWAI_SYSTEMD_UNIT` and `KAWAI_LAUNCHD_LABEL` replace the `AGENTBOARD_*` overrides.
6. **Docs:** the README, installer READMEs, current docs (including `docs/operations/database-backups.md`), `AGENTS.md`, the Purpose text of three main specs, user-visible strings, and comments use the new names; a final grep gate allows only the named compat sites.

Generated names change with no fallback: temp and upload prefixes, the pipe-pane directory, paste file names, the bootstrap window `__kawai_root__`, the update staging prefix, the systemd drop-in `50-kawai-update.conf`, log prefixes (`[kawai]`, `[kawai:settings]`), and `scripts/kawai-window.sh`.

Acceptance is written as decision tables and properties in design.md (E, K, H, T, R, U; PE, PH, PT, PU) with a parseable implementation contract. Table H (persistence and recovery) gets a blind second reading before any group-3 code, and the new startup reconciliations (data-home intent record; stored-target rewrite) get `docs/recovery-matrix.md` rows.

**Owner-only, not agent work:** the live cutover of the owner's install — its data directory and database, its service unit, the tmux session hosting live agents, and its profile chat-env wiring — and any release publication. Agents rehearse only with disposable homes, a private tmux socket, a compiled build outside `node_modules`, and a local release server.

Out of scope: historical records stay as written (`openspec/changes/archive/`, `.pl4n/`, `notes/`, and dated analyses such as `docs/refactor-analysis/`). Unprefixed variables (`TMUX_SESSION`, `LOG_FILE`, `PRUNE_WS_SESSIONS`, `E2E_*`) and the existing `KAWAI_*` variables keep their names.

## Capabilities

### New Capabilities
- `runtime-naming`: the Kawai names of runtime identifiers (environment variables, data directory and its files, database backups, tmux sessions, browser storage keys, service units) and how legacy `agentboard` names stay accepted or get migrated without losing data, including recovery from an interrupted migration.

### Modified Capabilities
- `app-updates`: the installed paths are `bin/kawai` and `dist/client`, a legacy `bin/agentboard` root still updates and keeps both names, source runs install under `~/.kawai/app`, and the tarball is `kawai-<platform>.tar.gz`.
- `github-workflows`: build artifacts are named `kawai-<platform>` and contain `bin/kawai`. During the transition window, releases also publish the legacy tarballs, and the checksum file covers both.
- `terminal-streaming`: `KAWAI_WS_DEFLATE` and `KAWAI_LOG_MATCH_YIELD_MS` replace the old variable names.
- `chat-sessions`, `claude-session-profiles`: the global provider environment comes from `KAWAI_CHAT_ENV`. The profile blocks restate current main text with only that rename.
- `chat-debug`, `openspec-visibility`, `workspace-navigation`: requirement text says Kawai instead of Agentboard. The behavior does not change.

## Impact

- **Code:** the sites in design.md "Current inventory at f52963d0" — chiefly `config.ts`, `db.ts`, `dbSafety/backupFiles.ts`, `bootstrap.ts`, `tmuxEnv.ts`, `tmuxFormat.ts`, `SessionManager.ts`, `sessionRefreshWorker.ts`, `startupPreflight.ts`, `remoteSessions.ts`, `chat/chatProviderEnv.ts`, `chat/codexProfiles.ts`, `chat/developmentFixture.ts`, `terminal/*`, `routes/paste*.ts`, `updates/*`, and the four persisted client stores. New pieces: one env-lookup helper, a data-home resolver with its migration and startup reconciliation, and a storage-key migration.
- **Tests:** the unit and integration tests that name the legacy identifiers (56 `src/` files mention an `AGENTBOARD_*` name including tests), 48 `tests/e2e/*` files and their support helpers, `playwright.config.ts`, `scripts/test-preload.ts`, `scripts/test-runner.ts`, and the fixture lister and its test.
- **CI/CD:** `.github/workflows/ci.yml` (the fixture step), `release.yml`, and `local-runner-test.yml`, `scripts/release-checksums.sh`, `scripts/release.ts`, `scripts/ios-sim.sh`, and `scripts/verify-terminal-render-latency.mjs`.
- **Deployment:** existing installs keep running without changes and self-update through the legacy tarball. Their data moves to `~/.kawai/` on the first start of the renamed build, after a backup. Moving service definitions to the new names requires re-running `systemd/install.sh` or `launchd/install.sh`. Shell profiles keep working but log deprecation warnings until their variables are renamed.
- **Dependencies (serialization, not prerequisites):** shared requirements with `mimo-million-token-context` and the proposed `provider-credential-store` ("Named profiles configure independent provider sessions"; "Operators configure the chat provider from Settings"), with the owner-held `fast-chat-switching` ("WebSocket compression is opt-in"), and with `team-workspace-redesign` (workspace-navigation) — whichever archives later re-derives the block from then-current main. Group 1 runs in a quiet window after the dev-checks archives because `AGENTBOARD_CHAT_FIXTURE` gates the fixture lister and CI step. No change must wait for rename to land.
- **Follow-up:** a later change drops the legacy tarballs, the `AGENTBOARD_*` fallback, and the legacy tmux, remote, and storage names once installs have moved.
